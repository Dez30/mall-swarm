02

端到端购物主链路

前台交易不是单个接口，而是一组跨服务、跨存储的状态推进。

01 / DISCOVER浏览商品首页聚合、商品搜索、详情与 SKU
02 / CART加入购物车同会员 + 商品 + SKU 合并数量
03 / CONFIRM生成确认单促销、地址、可用券、积分与金额
04 / ORDER提交订单锁库存、占用券、扣积分、写订单
05 / PAY支付回调待付款 → 待发货；锁库存转实扣
06 / FULFIL发货与收货后台发货；前台确认已发货订单
07 / AFTERSALE退货申请创建待处理申请，后续由后台处理

订单状态主线

0 待付款→1 待发货→2 已发货→3 已完成 待付款也可进入4 已关闭；模型另定义 5 = 无效订单
支付分支

只有状态仍为 0 的订单才能改成 1。状态变更成功后，订单明细按 SKU ID 排序，逐个减少真实库存和锁定库存。

取消分支

只有状态仍为 0 的订单才能改成 4。随后释放锁定库存、返还优惠券和已使用积分；已支付或已取消订单直接跳过。

“后台发货”发生在 mall-admin，不是 portal 接口；此处仅用于说明完整履约链路。portal 提供待发货到已完成之间的用户确认收货动作。

会员与认证

验证码 → 注册 / 改密 → 登录 → Session + Redis 会员缓存。

方法接口访问业务说明
POST/sso/register公开用户名、密码、手机号、验证码注册
POST/sso/login公开BCrypt 校验密码，返回 token 与 tokenHead
GET/sso/info会员获取当前会员资料；Redis 未命中时查 MySQL 并回填
POST/sso/logout会员删除会员资料缓存并注销当前 Sa-Token 会话
GET/sso/getAuthCode公开生成六位数字验证码，写 Redis 并在响应中返回
POST/sso/updatePassword会员按手机号和验证码更新 BCrypt 密码，删除会员缓存

注册流程

  1. 校验验证码

    读取 mall-swarm:ums:authCode:{telephone} 并比较，失败抛“验证码错误”。

  2. 检查账号唯一性

    按用户名相同 OR 手机号相同查询，存在则拒绝。

  3. 创建会员

    BCrypt 加密密码，设置启用状态；有默认等级则关联默认会员等级。

  4. 写入 MySQL

    插入 ums_member，注册接口本身不自动登录。

登录与当前会员

  1. 凭据校验

    依次检查非空、用户存在、密码正确、账号启用。

  2. 建立会话

    StpMemberUtil.login(memberId)，将 UserDto 写入会员 Session。

  3. 返回令牌

    客户端保存 token，后续以 Bearer 方式放入 Authorization。

  4. 资料读穿缓存

    Session 提供会员 ID；优先读 Redis，未命中查库并缓存 24 小时。

当前验证码是演示实现

没有短信发送、频率限制或验证成功后的删除逻辑；验证码直接返回且 90 秒内可重复使用。/sso/info 返回完整 UmsMember，代码未剔除 password 哈希。

购物车与促销计算

购物车保存用户选择，价格与优惠在查询促销列表时按最新商品数据重新计算。

方法接口访问业务说明
POST/cart/add会员新增购物车项；同商品 + SKU 已存在时累加数量
GET/cart/list会员当前会员未删除购物车项
GET/cart/list/promotion会员购物车 + 最新促销 + 可用库存；可选 cartIds
GET/cart/update/quantity会员按 id + memberId 修改数量，要求 quantity > 0
GET/cart/getProduct/{productId}会员获取商品和 SKU，供重选规格
POST/cart/update/attr会员软删旧项，再按新规格执行 add / 合并
POST/cart/delete会员按 ids + memberId 批量软删
POST/cart/clear会员软删当前会员全部购物车项

加入购物车

  1. 校验数量

    数量为空或小于等于 0 时直接拒绝。

  2. 绑定当前会员

    服务端覆盖 memberId、memberNickname 和 deleteStatus。

  3. 查找已有项

    条件为当前会员、商品 ID、未删除；SKU ID 非空时追加 SKU 条件。

  4. 新增或合并

    不存在则插入；存在则累加数量并更新修改时间。

促销计算

  1. 限定数据范围

    先取当前会员购物车；cartIds 非空时仅保留选中项。

  2. 按 SPU 分组

    阶梯折扣数量与满减金额以同一 productId 下的购物车项汇总。

  3. 加载商品最新数据

    批量查询 SKU、原价、促销价、优惠规则和赠送积分 / 成长值。

  4. 返回促销视图

    计算 price、reduceAmount、promotionMessage、realStock。

TYPE 1

单品促销

price 取 SKU 原价，reduceAmount = 原价 − 促销价。

TYPE 3

阶梯折扣

按 SPU 总件数匹配最高满足档位，原价 × 折扣。

TYPE 4

满减

按 SPU 原价总额匹配最高满足档位，再分摊到购物车项。

两个容易误读的参数行为

cartIds=null 或空列表表示使用当前会员整个购物车；只有非空列表才做筛选。购物车只是展示与下单输入，不在加购时锁库存。

确认单与创建订单

交易核心：所有价格、优惠、积分和库存均以服务端本次计算为准。

方法接口访问业务说明
POST/order/generateConfirmOrder会员请求体为购物车 ID 数组，返回促销商品、地址、可用券、积分规则和金额
POST/order/generateOrder会员创建待付款订单并返回 order + orderItemList

确认单：聚合但不占用资源

选中购物车最新促销 / 库存视图
+
会员资产地址 / 可用券 / 积分
+
积分规则本地缓存，60 秒延迟刷新
→
ConfirmOrderResult展示金额，不落订单

确认单金额 = 商品原价总额 − 活动优惠；此阶段尚未扣减优惠券和积分，也不锁库存。提交订单时会重新计算，不能把确认单金额视为最终支付依据。

创建订单请求

POST /mall-portal/order/generateOrder
Authorization: Bearer <token>
Content-Type: application/json

{
  "memberReceiveAddressId": 12,
  "couponId": 34,
  "useIntegration": 100,
  "payType": 1,
  "cartIds": [56, 57]
}

couponId、useIntegration 可空；payType：1 支付宝、2 微信。收货地址 ID 必填。

事务内的执行顺序

  1. 读取本次购物车与促销

    按当前会员和 cartIds 获取最新数据；拒绝数量为空或小于等于 0 的购物车项。

  2. 构造订单商品快照

    复制商品、SKU、价格、数量、促销和赠送积分 / 成长值。

  3. 预检可用库存

    检查 stock − lockStock ≥ quantity；预检不是最终并发保障。

  4. 计算优惠券

    重新验证可用性，按全场 / 分类 / 商品范围及商品价格占比分摊。

  5. 计算积分抵扣

    校验会员积分、使用门槛、能否与券共用、单笔最高抵扣比例并分摊。

  6. 原子锁定库存

    购物车项按 SKU ID 排序，逐个执行条件 UPDATE；任一失败即抛异常。

  7. 计算订单金额与快照

    计算总额、促销、券、积分和应付金额；读取地址，生成 Redis 每日自增订单号。

  8. 写入订单主从表

    插入 oms_order（status=0），再批量插入 oms_order_item。

  9. 占用资产并清购物车

    原子占用券、条件扣减积分；失败回滚。成功后软删本次购物车项。

  10. 注册提交后动作

    事务提交后发送延迟取消消息；发送异常记录日志，由定时扫描兜底。

事务边界

OmsPortalOrderServiceImpl.generateOrder 使用 @Transactional(rollbackFor = Exception.class)。库存锁定、订单写入、券占用、积分扣减和购物车删除处于同一本地数据库事务中；Redis 订单号递增和 RabbitMQ 不属于该本地事务。

库存锁定条件

UPDATE pms_sku_stock
SET lock_stock = lock_stock + #{quantity}
WHERE id = #{skuId}
  AND stock - lock_stock >= #{quantity}

订单应付金额

商品总额 + 运费 − 活动优惠 − 优惠券 − 积分抵扣。

当前运费固定为 0；优惠按商品分摊，订单金额由订单项汇总。

SKU 按固定顺序加锁，用于降低多商品订单交叉加锁导致死锁的概率。

空选集不是显式拒绝

cartIds 为空列表会按“整个购物车”处理；如果非空 ID 列表筛不到任何购物车项，当前代码没有“订单项不能为空”的显式校验。调用方应确保选中项有效，后续治理建议在服务端补齐该校验。

支付与库存扣减

支付发起、异步通知、主动查单和演示支付最终都收敛到订单支付成功逻辑。

方法接口访问业务说明

发起支付

  1. 按 outTradeNo 查询订单

    订单号不能为空、订单必须存在且 status=0。

  2. 服务端确定金额

    total_amount 使用数据库 order.payAmount，客户端 AliPayParam.totalAmount 不参与支付金额。

  3. 创建支付宝请求

    PC 使用 FAST_INSTANT_TRADE_PAY，WAP 使用 QUICK_WAP_WAY；设置异步 notifyUrl 和同步 returnUrl。

  4. 返回表单 HTML

    浏览器提交表单后在支付宝侧完成支付；同步跳转不是最终入账依据。

重复通知 / 支付取消竞态

订单从 0 → 1 的条件更新是状态闸门。影响行数为 0 表示已支付或已取消，抛“订单状态已变更”，不会继续重复扣库存。

事务与支付宝重试

paySuccess 内任一 SKU 实扣失败都会回滚订单状态和本事务内已扣库存。异步回调处理成功返回 success，失败返回 failure 或抛异常，供支付宝重试。

  1. 尝试关闭订单

    UPDATE oms_order SET status=4 WHERE id=? AND status=0；影响行数为 0 直接结束。

  2. 释放 SKU 锁定库存

一致性与实现边界

理解现有保护，也识别尚未封闭的业务入口；以下为静态代码结论。

已经具备的关键保护

DB

条件更新防超卖

库存锁定 SQL 自带可用库存条件，影响行数决定成败；多 SKU 固定顺序加锁。

TX

本地事务回滚

下单、支付成功、取消订单的数据库写操作有事务边界。

CAS

状态闸门

支付与取消都要求订单仍为待付款；券占用和积分扣减也使用条件 UPDATE。

PAY

服务端金额

支付表单金额取订单；回调同时校验签名和金额。

MQ

提交后发送

延迟消息在事务提交后发送，并有发布确认、退回日志。

JOB

定时任务兜底

消息失效时仍可扫描并取消超时订单，避免库存长期锁定。

阅读和后续治理时应重点关注

归属
部分订单与支付入口未校验会员归属

/order/detail/{orderId}、/order/cancelUserOrder、/order/cancelOrder 的当前服务路径没有当前会员条件；支付宝 pay / webPay / query 还在网关公开白名单中。模拟支付和确认收货已有归属校验，可对照理解。

售后
退货申请信任客户端订单和商品快照

未查询订单归属、订单商品、数量价格或重复申请；memberUsername 也来自请求体。

并发
优惠券领取不是原子流程

“查库存 / 限领 → 插历史 → 更新模板计数”没有事务和条件库存更新，存在并发超领及部分写入风险。这里的保护不同于下单时的券状态原子占用。

事务
部分多步写入缺少事务与归属条件

购物车规格修改先按 ID 软删旧项再新增，方法无事务且旧项更新未限定会员；默认地址切换也是两次独立写操作。浏览历史按 Mongo ID 批量删除未限定当前会员。

输入
公开商品查询的可见性与空值处理不统一

商品搜索和品牌商品列表只过滤删除状态、未统一过滤上架状态；商品详情未显式处理商品不存在。多个请求体未使用 @Valid，空选集、分页边界等依赖运行时或数据库行为。

缓存
会员与订单配置存在缓存语义

会员资料缓存 24 小时，依赖显式删除保持刷新；订单设置和积分规则通过 volatile 引用本地缓存，每 60 秒 fixedDelay 刷新，多实例不会实时同步。

文档性质

本节用于帮助阅读当前实现，不代表本次已修改这些问题，也不替代真实数据库、消息队列、支付宝回调和并发场景测试。

建议的联调顺序

  1. 注册 / 登录，验证 Authorization 请求头和网关白名单。
  2. 准备上架商品、SKU 库存、地址、优惠券和会员积分。
  3. 加购并生成确认单，核对促销、券、积分和金额。
  4. 创建订单，核对订单主从表、锁定库存、券状态、积分和购物车。
  5. 分别验证支付成功、重复回调、用户取消、MQ 超时取消和定时扫描兜底。
  6. 后台发货后确认收货，最后验证退货申请与 Mongo 个人资产。
